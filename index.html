ເກັບໃນເຄື່ອງເທົ່ານັ້ນ
ກຳລັງໃຊ້ຂໍ້ມູນຕົວຢ່າງ ແຜນຂາຍ, ສະຕັອກ ແລະ ການຮັບເຂົ້າແບບຕົວຢ່າງ ເພື່ອໃຫ້ເຫັນວ່າແຕ່ລະໜ້າເຮັດວຽກແນວໃດ. ລຶບອອກເມື່ອພ້ອມໃສ່ຂໍ້ມູນຈິງ.

ຈະຂາຍເທົ່າໃດ?

ໃສ່ຈຳນວນຈອກທີ່ຄາດວ່າຈະຂາຍ ແລ້ວລະບົບຈະຄິດຈາກສູດວ່າ ແຕ່ລະວັດຖຸດິບຈະໃຊ້ໄປເທົ່າໃດ ທຽບກັບສະຕັອກທີ່ມີ ແລະ ອັນໃດຈະບໍ່ພຽງພໍ.

ຄວາມຕ້ອງການ ທຽບ ສະຕັອກທີ່ມີ

ແທ່ງສີທອງ = ຈຳນວນທີ່ຈະໃຊ້ · ແທ່ງສີຂຽວ = ສະຕັອກທີ່ມີຢູ່. ຖ້າແທ່ງທອງຍາວກວ່າແທ່ງຂຽວ ແປວ່າ ວັດຖຸດິບນັ້ນຈະບໍ່ພຽງພໍ ຕ້ອງສັ່ງເພີ່ມ.

ຕາຕະລາງ ຄວາມຕ້ອງການ ທຽບ ສະຕັອກ

ຄໍລຳ “ຂາດ/ເຫຼືອ” ຕິດລົບ ໝາຍເຖິງ ຕ້ອງສັ່ງຊື້ເພີ່ມ.

ແຕ່ລະອາທິດ — ຈອກ ແລະ ລາຍຮັບ

ແທ່ງ = ຈຳນວນຈອກ, ເສັ້ນ = ເງິນ. ອາທິດ 5 ປົກກະຕິສັ້ນກວ່າ ຈຶ່ງເຫັນໜ້ອຍກວ່າ.

ເງິນຂາຍ 1 ກີບ ໄປໃສ່ຫຍັງ

ວັດຖຸດິບຕາມສູດ, ຂອງເສຍຕາມ Q factor, ສ່ວນທີ່ເຫຼືອແມ່ນກຳໄລຂັ້ນຕົ້ນ ກ່ອນຄ່າເຊົ່າ ຄ່າແຮງ ແລະ ຈອກ.

ໃຊ້ໄດ້ອີກຈັກອາທິດ — ອັນໃດຈະໝົດກ່ອນ

ສະຕັອກທີ່ມີ ຫານດ້ວຍ ການໃຊ້ 1 ອາທິດ. ຕ່ຳກວ່າ 1 ອາທິດ (ສີແດງ) ຄື ຈະບໍ່ພໍໃຊ້ໃນອາທິດໜ້າ.

ກຳໄລແຕ່ລະເມນູ

ກຳໄລຂັ້ນຕົ້ນເປັນກີບ. ແທ່ງສັ້ນ = ຂາຍໄດ້ຫຼາຍ ແຕ່ໄດ້ກຳໄລໜ້ອຍ.

12 ລາຍການ ທີ່ໃຊ້ເງິນສັ່ງຊື້ຫຼາຍທີ່ສຸດ

ລາຍຮັບຕາມເມນູ (12 ອັນດັບ)

ຈຳນວນຈອກທີ່ວາງແຜນຂາຍ ແຕ່ລະອາທິດ

ໃຊ້ຄືກັບ Excel: ກົດລູກສອນ ຫຼື Enter ເພື່ອຍ້າຍຊ່ອງ, Tab ໄປຂວາ, ແລະ copy ຈາກ Excel ມາ paste ທັງບລັອກໄດ້ເລີຍ. ພິມແລ້ວເກັບໃນເຄື່ອງທັນທີ — ກົດ ບັນທຶກແຜນ ເພື່ອສົ່ງຂຶ້ນຄລາວ.

ລາຍການສັ່ງຊື້

ຈຳນວນທີ່ຕ້ອງສັ່ງ = ທີ່ຈະໃຊ້ + ຂອງເສຍ + ສະຕັອກສຳຮອງ − (ສະຕັອກຕົ້ນເດືອນ + ທີ່ຮັບເຂົ້າແລ້ວ). ປັດຂຶ້ນເປັນຈຳນວນຖົງເຕັມ.
ສະຕັອກທ້າຍເດືອນ = ຕົ້ນເດືອນ + ຮັບເຂົ້າ − ໃຊ້ໄປ. ເມື່ອປິດເດືອນ ຕົວເລກທ້າຍເດືອນຈະກາຍເປັນຕົ້ນເດືອນຂອງເດືອນໜ້າ. ຖ້ານັບຂອງຈິງ ໃຫ້ໃສ່ໃນຊ່ອງ “ນັບຈິງ” ແລ້ວຈະເຫັນຜົນຕ່າງວ່າຫາຍໄປເທົ່າໃດ.

ບັດສະຕັອກລາຍເດືອນ

ລາຍການວັດຖຸດິບ

ຕົ້ນທຶນຕໍ່ກຣາມ ເປັນຕົວກຳນົດຕົ້ນທຶນຂອງທຸກສູດ. ໃສ່ລາຄາເປັນບາດ ຫຼື ກີບ ກໍ່ໄດ້ — ອີກຊ່ອງໜຶ່ງຈະຄິດຕາມອັດຕາແລກປ່ຽນ.

ເມນູ ແລະ ເບສ

ເບສ (ບໍ່ມີລາຄາຂາຍ) ຄືສ່ວນປະສົມທີ່ເອົາໄປໃຊ້ໃນເມນູອື່ນ. ຕົ້ນທຶນຕໍ່ກຣາມຂອງເບສ ຄິດຈາກວັດຖຸດິບຂອງມັນເອງ ລົງໄປທຸກຊັ້ນ.

ບັນຊີຜູ້ໃຊ້ ແລະ ສິດ

ຜູ້ຈັດການ (admin) ເຫັນ ແລະ ແກ້ໄຂໄດ້ທຸກຢ່າງ. ພະນັກງານ (staff) ໃສ່ແຜນຂາຍ, ນັບສະຕັອກຈິງ ແລະ ເບິ່ງລາຍການສັ່ງຊື້ໄດ້ ແຕ່ບໍ່ເຫັນຕົ້ນທຶນວັດຖຸດິບ, ຕົ້ນທຶນສູດ, ລາຍຮັບ ຫຼື ກຳໄລ.
ໃຫ້ພະນັກງານສ້າງບັນຊີເອງຢູ່ໜ້າ login ກ່ອນ ແລ້ວຊື່ຈະຂຶ້ນມາໃນຕາຕະລາງນີ້ ຈຶ່ງຕັ້ງສິດໃຫ້ໄດ້.

Firebase

ຂໍ້ມູນທັງໝົດເກັບເປັນເອກະສານດຽວໃນ Firestore ທີ່ shops/{ລະຫັດຮ້ານ}. ທຸກເຄື່ອງທີ່ login ດ້ວຍໂປຣເຈັກດຽວກັນ ຈະເຫັນຂໍ້ມູນຄືກັນ.
ກົດລະບຽບ Firestore ທີ່ຄວນໃສ່ 
rules_version = '2';
service cloud.firestore {
  match /databases/{db}/documents {
    match /shops/{shop} {
      allow read, write: if request.auth != null;
    }
  }
}
ກົດລະບຽບນີ້ຮຽກຮ້ອງໃຫ້ login ກ່ອນ. ການເຊື່ອງຕົ້ນທຶນຈາກພະນັກງານ ເປັນການເຊື່ອງໃນໜ້າຈໍ — ຄົນທີ່ຮູ້ເລື່ອງເທັກນິກ ຍັງອາດອ່ານຂໍ້ມູນດິບໄດ້. ຖ້າຕ້ອງການປ້ອງກັນແທ້ ຕ້ອງແຍກເອກະສານຕົ້ນທຶນອອກ ແລ້ວຕັ້ງກົດລະບຽບຕາມສິດ.
